# ADR 0001: Expo (CNG) or bare React Native

Status: accepted
Date: 2026-10-14
Decision: expo

> `Decision:` is `expo` or `bare`. `Status:` becomes `accepted` only after the user agrees.

## Context

Loto Quine (PRD v0.1.0) is a portrait, tap-driven caller app: one big animated ball, a 1-90 board (90 static cells),
a few screens and dialogs. Its needs that matter for the stack:

| Need (PRD) | Library | Expo prebuild / New Architecture |
|---|---|---|
| Ball roll/reveal animation, confetti burst, board highlight | `react-native-reanimated` 4 (+ worklets) | Expo SDK module set, New Arch only (fine) |
| Glossy ball, warm gradients | React Native `experimental_backgroundImage` gradients (RN 0.86), fallback `react-native-svg` | core / Expo-supported |
| French voice announcement, offline | `expo-speech` (Android TextToSpeech, fr-FR, no permission) | first-party Expo module |
| Screen stays on during Game / Check | `expo-keep-awake` (`useKeepAwake` on those screens) | first-party Expo module |
| Rolling and festive sounds | `expo-audio` + `expo-asset` (no RECORD_AUDIO, plugin not added) | first-party Expo module |
| Vibrations | `expo-haptics` | first-party Expo module |
| Game state, settings, consent persistence | the factory overlay's storage (AsyncStorage) | supported |
| Deep link `lotoquine://seed/<n>` (testing aid) | `scheme` in `app.config.js` + `expo-linking` | config only |
| Opt-in Analytics + Crashlytics | `@react-native-firebase/app`, `/analytics`, `/crashlytics` v26 | official config plugins |

No sensor, no custom native code, no physics, fewer than ~100 animated elements: Views + Reanimated are enough,
Skia is not needed. Build is local on Windows (prebuild + Gradle), APK sideloaded; no cloud build.

Points to confirm at scaffold/build time: `expo-speech` declares the `TTS_SERVICE` package-visibility query needed
on Android 11+ (add it with a small config plugin if not); the gradient API renders as expected (otherwise
`react-native-svg`).

## Criteria

| Criterion | Weight | Expo (CNG + prebuild) | Bare React Native | Notes |
|---|---|---|---|---|
| All required libraries work with Expo prebuild / config plugins | high | yes: all first-party Expo modules or official plugins | yes | nothing forces bare |
| Need to hand-edit native Android code continuously | high | no need | not needed either | only manifest tweaks, doable with config plugins |
| Custom native module (Kotlin/C++) needed | medium | no | no | TTS, keep-awake, haptics are covered by Expo modules |
| Upgrade effort over time | medium | low: bump SDK, `npx expo install --fix` | higher: Upgrade Helper native diffs | |
| Build simplicity on this machine (local Gradle) | medium | proven by guess-animal (SDK 57, `build-apk.mjs`) | works, not yet proven in the factory | |
| Firebase setup effort | low | config plugins | manual Gradle setup | |

## Decision

**Expo (CNG, local prebuild), rendering with React Native Views + Reanimated.**

1. Every need of the PRD is covered by first-party Expo modules (`expo-speech`, `expo-keep-awake`, `expo-audio`,
   `expo-haptics`) or official config plugins (React Native Firebase); no native code to write.
2. The factory has already shipped an Expo SDK 57 app end to end on this machine (guess-animal), so build, verify
   and release are proven.
3. Upgrades stay cheap (`android/` is generated, not merged by hand).

## Consequences

- Easy: adding Expo modules with `npx expo install`, regenerating `android/` at each build, Firebase via plugins.
- Harder: any manifest or Gradle change must go through `app.config.js` or a small config plugin (e.g. the TTS
  query if missing), never by editing `android/`.
- Expo: `android/` is generated by `npx expo prebuild` and git-ignored; native changes go through config plugins.
- Text-to-speech quality depends on the phone's installed French voice (Google TTS on most phones); the app stays
  usable silently without it (PRD).

Amendment 2026-10-14 (build): animations use React Native's built-in Animated API with the native driver instead of
Reanimated: one ball, a short confetti burst and a static board do not need it, and it keeps one dependency out.
The gradients use `experimental_backgroundImage` (radial-gradient), so `react-native-svg` is not needed either.
`expo-speech` declares the Android 11+ `TTS_SERVICE` package query in its own manifest (checked in node_modules).

## Alternatives considered

- Bare React Native: same libraries would work, but it adds native upgrade work and an unproven build path in the
  factory, with no benefit for this app.
- Skia rendering: unnecessary for one ball, a static board and a short confetti burst; it would add ~5-8 MB to the APK.
- Pre-recorded Azure voice (as in guess-animal): rejected by the brief (the phone's built-in voice is used).
